
## 2024-05-28 - Missing HTML Escaping in History View Rendering
**Vulnerability:** Found multiple Cross-Site Scripting (XSS) vulnerabilities in `src/pages/history.js` where user-controlled strings (like workout notes, day names, plan names, and exercise names) were directly interpolated into HTML strings via template literals and injected using `.innerHTML`.
**Learning:** Even when a utility like `escapeHTML` is available and used in parts of a template (e.g., `workout.notes`), it is incredibly easy for developers to overlook other dynamic, user-provided fields in the same template string (like `w.dayName`, `ex.name`, etc.). The inconsistency of escaping is a major vulnerability pattern in this application architecture that relies on Vanilla JS `.innerHTML`. Furthermore, escaping IDs (like `ex.id`) necessitates switching to `[id="..."]` attribute selectors instead of `#...` hash selectors to prevent query selector syntax errors if special characters exist.
**Prevention:** Audit all `.innerHTML` assignments project-wide. Mandate that every user-controlled variable interpolated into a template literal rendered as HTML must be wrapped in `escapeHTML`. Standardize on `[id="..."]` for DOM selections that rely on dynamic IDs.
